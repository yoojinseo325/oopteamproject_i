# 팀 공유와 Version 2 / 3 확장

## 첫 공유 때 함께 볼 것

V1은 합의와 확장의 출발점입니다. 팀원이 코드를 읽지 않은 채 그대로 최종 제출하는 방식보다, 클래스 책임과 화면 흐름을 함께 확인하고 각자 맡을 부분을 정하는 데 사용하세요.

권장 첫 회의(약 40분):

1. 5분: `run.cmd`로 실행하고 팀원마다 사용자 하나 만들기.
2. 10분: 첫 단계에서 일부러 판정 또는 단서를 틀리고 다음 단계의 다른 조건 재출제 확인. 종료 후 재실행하여 기록 복원 확인.
3. 10분: ARCHITECTURE와 DATA_FORMAT을 보고 “버튼 → 서비스 → 파일” 흐름 따라가기.
4. 10분: 담당 클래스·메서드·데이터 ID 범위 정하기. 모든 팀원이 최소 한 클래스의 구현/개선 책임을 맡기.
5. 5분: 다음 통합일과 테스트 기준을 정하고 실제 회의록에 기록하기.

이 문서는 계획 제안입니다. 실제 팀원 이름, 기여, 회의 내용, 교수 피드백을 만들어 넣지 않았습니다.

## 담당 구역 예시

팀 인원에 맞춰 합치거나 나누세요. 통합 담당도 구현 책임을 가집니다.

| 구역 | 시작할 클래스 | 독립적인 개선 예시 |
|---|---|---|
| 통합·앱 시작 | App, MainFrame | 화면 클래스 분리, 경로 설정, 통합 빌드 |
| 퀴즈 상태·채점 | QuizSession, Question, QuizPanel | 새로운 미션 단계, 중간 이어하기 |
| 장면 표현 | Scene, FieldPanel | 좌표 검수, 애니메이션, 클릭 영역 개선 |
| 콘텐츠·사전 | RuleConcept, Catalog | 규칙 검색 개선, 데이터 검수 도구 |
| 저장·사용자 | Repository, FileRepository, UserProfile | 마이그레이션, 백업, 프로필 관리 |
| 복습·성장 | LearningService, StepSelector | 규칙별 복습 간격, 전이 문항 출제 |
| 메모·사용성 | StudyNote, Theme, 향후 NotesPanel | 메모 수정, 키보드/접근성, UI 시험 |

공유 인터페이스가 바뀌면 미리 예제 호출과 반환값을 합의하세요. 예를 들어 FieldPanel 담당은 “좌표 클릭 시 어떤 tokenId를 전달할지”, 저장 담당은 “save가 실패했을 때 어떤 예외를 줄지”를 정합니다.

## Version 2: 통합 중간점검용

목표는 새 기능을 많이 나열하는 것보다, 팀원 모두가 데이터와 화면을 연결한 코드를 설명할 수 있게 만드는 것입니다.

- MainFrame의 사전/메모/기록 화면을 별도 Panel 클래스로 분리해 병렬 작업 충돌 줄이기.
- 프로필 닉네임 수정, 메모 수정, 문항 검수용 미리보기 추가.
- 기본·응용 외에 처음 보는 전이 문항을 규칙당 1~2개 추가. 목표 24~30문항.
- 주자 이동을 `javax.swing.Timer`로 표현하되 정지 화면과 텍스트 설명도 제공.
- `RuleProgress` 도입: 문항 암기와 규칙 이해를 구별하는 진도 설계.
- 최소 3명에게 도움 없이 실행해 보게 하고, 막힌 위치와 오해한 표현을 실제로 기록.
- 기존 기록을 유지한 채 업데이트되는지 검사.

완료 기준: 팀원별 담당 코드 설명, 신규 데이터 로딩, 단계 진행/자동 재도전/재실행 시연, 저장 오류 메시지, 실행 ZIP 재검증.

## 안내문 일정과 팀 운영

업로드된 2026-10-26 안내문에 따르면 중간점검은 **11월 16·17일**, 발표·시연은 **11월 30일·12월 1일**입니다. 본인 분반에 맞는 날짜를 선택하세요. 최종 제출은 안내문에 12월 14·15일로 구분되어 있으므로 분반과 후속 공지를 확인해야 합니다.

안내문에는 주 1회 이상 회의록, 모든 팀원의 최소 한 클래스 개발 책임, 역할 합의와 통합, 코드 이해, 영상·보고서 등 제출물도 포함되어 있습니다. V1 소프트웨어와는 별도로 팀이 실제 수행해야 할 사항입니다. OTP/LMS에 제출하거나 팀원에게 메시지를 보내는 작업은 이 프로젝트 생성에 포함하지 않았습니다.

## 시연 순서 (약 4분)

1. 홈에서 STEP 1을 시작하고 아직 열리지 않은 단계의 내용이 숨겨져 있음을 확인한다.
2. 장면 전환 후 올바른 판정과 단서를 선택해 해설을 확인한다.
3. STEP 2의 응용 문제에서 다른 조건을 보여주고 일부러 틀린다.
4. STEP 3으로 진행해 이전에 틀린 규칙이 새 상황 사이에 다시 등장하는지 확인한다.
5. 발견한 규칙에서 “포스” 검색 → 북마크 추가 → 선택적으로 메모 작성.
6. 앱을 종료하고 재실행하여 기록이 남는 모습을 보여준다.
7. 담당 클래스와 파일 한 개씩을 열어 화면·서비스·저장소가 협력하는 구조를 설명한다.

## Git을 사용할 때

이 폴더에서는 원격 저장소 생성·업로드·커밋을 하지 않았습니다. 팀 저장소를 정한 뒤 `.gitignore`를 유지해 `userdata/`, `build/`, `dist/`를 제외하세요. 배포 ZIP/JAR는 저장소의 릴리스 파일로 별도 공유할 수 있습니다. 데이터 ID 변경과 파일 헤더 변경은 일반 UI 수정과 구별해 팀 전체에 알리세요.
