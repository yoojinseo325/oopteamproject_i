# V1 + V2 통합 안내

현재 버전은 **2.1.0**, 총 **26 STEP / 52문항 / 34개 개념**입니다. 모든 학습 화면은 기존 `baseup.App`으로 실행합니다.

## 가져온 내용

| 기반 | 유지·통합한 내용 |
|---|---|
| 로컬 V1.2 | 단계 진행, KBO 10구단·18명 선수의 12개 판정 문제, 24개 도식, 근거 선택, 복습, 사용자·기록·메모·북마크 |
| 팀 V2 | E/M/H/U 각 10문항, 총 40개 PNG 삽화, 질문·선택지·정답·해설·학습 카드 |
| 공통 | 단일 Question / QuizSession / LearningService, 공통 XP와 학습 경로, 하나의 MainFrame |

V2 원본은 [팀 저장소의 14b6bd1 커밋](https://github.com/yoojinseo325/oopteamproject_i/commit/14b6bd1), `BASEUP_CardLayout.(Version 2)/BASEUP_Java_Project/`입니다. PNG는 원본 바이트를 그대로 가져왔고 질문 ID·선택지·정답 순서를 유지했습니다. 질문 제목은 정답 용어가 노출되지 않도록 바꿨습니다. 원본과 별개로 만든 것은 U01~U10의 근거 선택지와 통합 STEP 배치입니다.

V2의 별도 앱 진입점·동명 MainFrame·채점기·익명 결과 저장소를 함께 컴파일하지 않습니다. 콘텐츠 편집은 아래 데이터 파일로 통일했습니다. V2의 자유 단계 선택과 정답 선공개 학습 화면은 순차 진행·제출 후 카드 공개 방식으로 합쳤습니다. V2의 문제 관리 GUI는 이 버전에 이식하지 않았습니다.

V2 삽화의 인물은 일반적인 야구 선수 그림입니다. KBO 선수·구단 이름과 정확한 팀색은 기존 V1 도식에 유지합니다. 삽화 속 유니폼을 실제 구단으로 임의 지정하거나 선수 초상으로 표시하지 않습니다.

## 팀원이 수정할 파일

| 작업 | 파일 |
|---|---|
| 그림 기초·판정 문항 | `data/image_questions.tsv`, `data/images/` |
| KBO 도식 판정 문항 | `data/questions.tsv`, `data/scenes.tsv`, `data/matchups.tsv` |
| 선수·구단 | `data/players.tsv`, `data/teams.tsv` |
| 개념과 제출 후 카드 | `data/rules.tsv` |
| 순서·STEP 확장 | `data/steps.tsv` |
| 화면·그림 | `ui/QuizPanel.java`, `ui/ImageView.java`, `ui/FieldPanel.java` |
| 출제·저장·복습 | `service/LearningService.java`, `service/StepSelector.java` |

1. 수정할 문항 ID 범위를 팀원끼리 나눕니다. 각자 기능 브랜치에서 작업합니다.
2. 같은 규칙은 기존 ruleId에 연결하고, 새 문항과 새 STEP에는 재사용하지 않은 ID를 부여합니다.
3. STEP의 ID는 순번이 아닙니다. 기존 ID의 문제 묶음을 바꾸면 완료 의미가 달라지므로 새로운 단계는 새 ID를 사용합니다.
4. 그림 문제는 단서 유무에 따라 입력 단계가 자동으로 바뀝니다. Java 화면을 추가할 필요가 없습니다.
5. `test.cmd`로 전체 검증 후 Pull Request에서 문항 조건·정답·근거와 변경 화면을 함께 검토합니다. 콘텐츠 수를 확장한 경우 테스트의 확정 콘텐츠 수 기대값도 검수 결과에 맞춰 갱신합니다.

150 STEP은 아직 생성하지 않았습니다. 구조상 고정된 6단계 제한은 제거했으므로 데이터로 확장할 수 있지만, 단계마다 검수된 문항과 근거를 먼저 작성해야 합니다.

## 기존 기록과 실행

`userdata/` 형식은 유지합니다. 기존 STEP ID 1~6의 완료 기록이 새로운 위치에 연결되고, 기존 문항 ID·XP·북마크·메모도 유지됩니다. 새로운 기초 단계는 새로 풀어야 합니다. V2의 익명 요약 결과 파일은 사용자·문항별 판단 근거를 알 수 없어 자동 병합하지 않습니다.

`build.cmd`로 빌드하고 `run.cmd`로 실행합니다. 배포하려면 `powershell -ExecutionPolicy Bypass -File scripts/package.ps1`을 실행하세요. 결과는 `dist/BaseUp-share.zip`이며 `data/images/`가 포함되고 개인 기록은 제외됩니다. JAR만 단독으로 옮기지 말고 ZIP의 전체 폴더를 옮기세요.
